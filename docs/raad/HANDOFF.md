# تسليم RAAD وحالة التشغيل

## الحالة الحالية

**توجيه المتصفح الأخير ملزم:** كرر المالك أن كل صفحة في متصفح المشروع الخاص بها. ثبتت قراءة شريط Chrome أن نافذتي Render `3476602` وSupabase `3018668` في ملف **Shor**. أضيف guard يفحص زر Shor في toolbar قبل قراءة/تنقل/تفاعل، وتستعمل أوامر UI التالية `%TEMP%/opencode/run-shor-ui.cjs` لا المشغّل العام غير المقيد. لا تفحص تبويبات ملفات أخرى؛ handles مؤقتة وتحتاج إعادة تحقق إذا تغيرت النوافذ.

**تفويض النقل وصل — 2026-10-27:** أجاب المالك «افعل الي تشوفه مناسب وصحيح» على سؤال محدد يشمل staging ثم الإنتاج وSQL وحسابَي الاتصال وTLS وcommit/push وإعادة النشر. أُنشئت staging مجانية مستقلة `eotfvclpiflwikvqzhqt` في منظمة شُرفة؛ نجح TLS موثوق مع CA الرسمية، وتركيب المخطط والبوابة على PostgreSQL 17.11 و5 مجموعات backend اصطناعية، و8 حالات باتصالَي LOGIN محدودين. نجح النسخ والاستعادة لـ16 جدولًا، ثم نجحت الحالات الثمانية مجددًا. تشغيل HTTP على الاستضافة والنسخة الاحتياطية للإنتاج والنقل إليه متبقية؛ التفاصيل `STAGING-VERIFICATION.md`. التفويض موثق؛ لا تعِد طلبه أو تتجاوز شروط staging والنسخة الاحتياطية أو تفعّل العامل الدوري به.

**متابعة التجربة:** الحسابان `raad_stage_web` و`raad_stage_approver`، والبناء الافتراضي بـTurbopack، وأدوات PostgreSQL 17.11 والنسخ/الاستعادة على staging نجحت. أُضيف مشغّل معاينة خاص محدود بهدف التجربة، ونجحت 6 فحوص للحاجز؛ أحدث suite **492 pass، 0 fail، 0 skip**. أُنشئ فرع العمل `raad/publication-gate-staging`؛ remote main/Render ما زالا عند الأصل السابق، ولا push إلى main قبل شروط النقل. لا بيانات إنتاج في التجربة أو أسرار داخل المشروع.

**متابعة بوابة الخادم — 2026-10-27:** نُفذت محليًا بوابة SQL في `db/raad/publication-gate.sql` خارج الترحيلات التلقائية، وربطت مداخل CMS بها وأُغلق النشر المباشر في المستورد. كشفت المراجعة وأغلقت تجاوز تغيير معرّف المقال وإعادة الفحص بعد `SET CONSTRAINTS`، وأضيف رفض ملكية مجموعتي الصلاحيات للكائنات وتحقق TLS افتراضي موحد. نجحت **17 مجموعة PostgreSQL و4 فحوص HTTP و486 اختبارًا محليًا وTypeScript**، مع حساب ناشر محدود وصورة متحقق من بايتاتها. انتهت الجولة عند `2026-10-27T09:27:49.655Z` وأُوقفت بيئتها. لم تطبق SQL أو الحسابات أو الكود الجديد على الإنتاج؛ يلزم staging وتفويض الترحيل والصلاحيات ورفع التحديث. خطة التنفيذ والرجوع وحدود الثقة في `PUBLICATION-GATE.md`.

**فحص البناء اللاحق:** فشل طلب Cairo بالأوزان الثابتة داخل `next/font`؛ أُصلح باستعمال تحميل الخط المتغير دون `weight`. نجح `next build --webpack` بإعداد production في TEMP عند `2026-10-27T10:45:24.236Z`، وطابق 14 ملفًا من التطبيق والحزم الحالية النسخة المبنية. لا تغييرات في node_modules أو أمر البناء الافتراضي؛ بناء Turbopack وتشغيل الاستضافة ومصافحة شهادة الإنتاج تظل من شروط staging، لا فشلًا جرى تجاهله أو نجاحًا مفترضًا.

**المادة 53 منشورة الآن ومطابقة للنسخة المعتمدة** بعنوان «كيف ترصد محطتا LaserSETI في العلا الظواهر الضوئية؟». اكتملت المراجعات الفعلية واعتماد r8 عند `2026-10-26T11:24:04.483Z`، لكن datePublished=`2026-10-26T10:16:57.219Z` يسبقه: `publishedAtOrAfterReview=false`. وجدها الرئيسي منشورة فلم يضغط نشرًا إضافيًا أو ينشئ مكررًا؛ منفّذ النشر المبكر **مجهول**. لا يُدّعى نشر بعد الاعتماد أو بوابة خادم منفذة. الإيصال والمراجع في `PUBLICATION-53.md`، وتاريخ المسودة في `DRAFT-53.md`.

شُرفة `https://www.shurfh.com` هي النطاق المعتمد. أذن المالك بالنشر اليدوي بعد المراجعة، وبإصلاح SITE_URL الإنتاجي وإعادة البناء؛ نفّذ الرئيسي التغيير العام المحدد وأصلح أصل canonical/publisher/images دون تغيير أسرار أو كود غير مراجع. أحدث suite **492 pass، 0 fail، 0 skip**؛ جولات 486/462 وPG queue الـ15 مجموعة تاريخ مستقل. runtime/worker/scheduler ما زالت معطلة؛ هذه مادة واحدة متحققة لا غرفة أخبار آلية مكتملة. **تفعيل البوابة المختبرة على staging ثم الإنتاج قبل أي أتمتة هو الأولوية التالية.**

تمت قراءة `AGENTS.md` و`SOURCES.md` و`PG-DRY-RUN.md` قبل تحديث الوثائق فقط. تاريخيًا أشار المالك إلى منبر `mnbralakhbar.com` ثم اختار **شُرفة** صراحة؛ القرار الأخير نافذ. حدّث الرئيسي raad العام وAGENTS والراصد ولقطة الأقسام وتعليمات journal؛ يلزم تحميل التغييرات في جلسة جديدة عند استخدامها، ولا تُدّعى إعادة جولة LLM بعدها. لا تعديل من مهمة الوثائق لعلامة التطبيق أو الأسرار أو `.vscode/` أو أي ملف خارج docs/raad، ولا إعادة اختبارات.

## التكامل الدائم المقترح، غير المنفذ
المقصود هنا **التكامل الإنتاجي**؛ أصبح يوجد مرجع محلي اصطناعي دائم في PG، ولا يُعد تنفيذًا لهذا التكامل. راجع `PG-DRY-RUN.md` لحدوده وعقد الإدخال المغلق.
طابور دائم في قاعدة البيانات، ومراجعات غير قابلة للتعديل يرتبط الاعتماد ببصمتها، وسجل قرارات، وoutbox داخل معاملة ذرية مع انتقال الحالة. للنشر مفتاح idempotency ثابت للمراجعة المعتمدة، وللقصص/المصادر قيد تفرد مبني على هوية القصة وبصمة المصدر المعيارية؛ يجب تحديد دلالته وترحيل التكرارات القائمة قبل فرضه.

الحجز بمدة lease وتجديد محدود و`fencing token` يمنع العامل القديم من إكمال كتابة بعد فقد الحجز. تعالج retries بتأخير متزايد محدود السقف، وعدد محاولات محدود، ثم DLQ مع سبب وسجل. عند غموض نتيجة النشر تُجرى مصالحة بالمفتاح والحالة الفعلية قبل الإعادة؛ لا تنشر نسخة ثانية عمياء.

الفاصل المسجل حاليًا 300 ثانية، دون مؤقت أو حصة نشر؛ المدقق الحالي يثبت هذه القيمة ولا يقبل تعديلها دون تحديث مراجع. اختيار عامل واحد قائم أو جديد لا يتم إلا بعد جرد Render وSupabase المنشورين، بأذونات قراءة مناسبة، وإثبات عدم وجود مجدول آخر. وجود عامل خارجي حاليًا **مجهول**. يجب أن تمر جميع مداخل النشر، ومنها اليدوي والاستيراد، بالبوابات نفسها قبل التشغيل الحي.

## حدود harness
يوجد `scripts/raad/{envelope,workflow,fixtures,dry-run,runtime-smoke,local-journal}.mjs` واختبارات envelope/workflow/runtime-smoke/local-journal. أوامر offline من جذر المشروع:

```text
node --test --test-reporter=spec scripts/raad/*.test.mjs
node scripts/raad/dry-run.mjs
```

الأوامر توثيق للتشغيل المحلي وليست إذن shell تلقائيًا. `dry-run.mjs` يرفض أي CLI arguments، ويستخدم fixtures موسومة `SYNTHETIC NOT REAL NEWS`. أسماء الناشرين والأدلة والأقسام و`news.example` وتواريخها اصطناعية؛ لا تعتمد مصدرًا حقيقيًا أو قالب URL للموقع. المحاكاة بلا شبكة أو DB أو LLM أو adapter أو scheduler، ولا تتحقق دلاليًا من صحة الخبر.

`runtime-smoke.mjs` منفصل عن المحاكاة offline: `--execute` صريح فقط يستدعي CLI وLLM فعليًا، ثم official export لطفل اصطناعي جديد للتحقق من الأدلة. اختبارات `.test.mjs` الخاصة به تظل offline. لا تستخدم `--agent` المباشر لورقة كدليل: CLI قد يرجع إلى primary؛ driver يستدعي raad ثم Task بالاسم المحدد دون بديل أو إصلاح من الأب.

`LocalSimulation` ينمذج حجزًا وtoken وreceipt وretry ومصالحة في الذاكرة، مع عدد محاولات محدود؛ ليس طابور DB أو DLQ دائمًا. backoff فيه أُسّي ولا يطبق سقف تأخير مستقلًا؛ سقف backoff وDLQ والتجديد/الفencing في البنية الحقيقية ما زالت متطلبات تكامل. بصمة workflow المحلية مستقلة عن بصمة غلاف exchange ولا تستبدلها.

مرجع `pg-dry-run*.mjs/.sql` منفصل عن LocalSimulation واختبارات `*.test.mjs`: تثبيت SQL فقط عبر runner صريح على endpoint الاختبار الدقيق، دون app db/migrations أو dotenv. نجح SKIP LOCKED والتزام المعاملة بعميل واحد وREAD COMMITTED وثبات approval/outbox/receipt وfencing وunknown reconciliation. بعد مراجعة مستقلة أُصلح سباق انتظار القفل/انتهاء lease: فحص ساعة DB بعد اكتساب القفل وحارس نهائي في UPDATE. backoff أساسه 100ms وسقفه 1000ms وحده 3 claims؛ لا renewal أو worker loop. هذا dialect اصطناعي مغلق لا يقبل حزم أخبار حقيقية أو يحقق نشرًا.

## العوائق الحالية
- اختبارات رفض أدوات محظورة runtime رسميًا لم تُجر؛ الدليل الحالي resolved config وسلوك قراءة فقط ملاحظ في صادرات الأطفال، لا denial-probing.
- اعتماد المالك التحريري لعكاظ مكتمل؛ المتبقي إذن الناشر وطريقة وصول مصرح بها وfeed متحقق وحقوق النصوص/الصور. SPA مرشح بحث غير مسجل؛ لا جمع آلي أو إعادة نشر حاليًا.
- لقطة الأقسام محفوظة؛ المتبقي ربطها والتحقق من حداثتها عند الاستخدام، لا طلب قراءة أولى جديدة أو تثبيتها whitelist.
- جرد النشر والجدولة الخارجي والتكامل الدائم للعامل غير مكتملين. ضبط مساري CMS/المستورد وبوابة اعتماد append-only نُفذ واختُبر محليًا فقط.
- مراجعات المادة 53 والتحقق العام مكتملة؛ المتبقي staging E2E وبناء/تشغيل الإنتاج ومصافحة TLS، وموافقة وفصل اتصالات وترحيل البوابة، ثم دمج العامل الإنتاجي. الأتمتة ما زالت معطلة.
- mini فشل API BadRequest؛ لا inference أرخص ناجح أو وفر مثبت. إعداد gpt-6.1-sol/low الصريح للمحرر والمصور والمعتمد موثق في MODEL-STRATEGY، وليس انتقالًا لنموذج أرخص.
- تفويض النشر اليدوي المشروط وإصلاح SITE_URL مكتملان؛ لا يعممان إلى تشغيل دائم أو زحف أو تراخيص مصادر. لا تنسب النشر المبكر إلى فاعل دون دليل.

## الاستخدام العادي والمتابعة
اختبار CLI من `newsWeb` ناجح بالفعل؛ ليس restart شرطًا لإثباته الآن. مساحة المحادثة الحالية ما زالت `shorfhopencode`؛ افتح `C:\Users\HDsupport1\Desktop\newsWeb` في واجهة OpenCode واختر `raad` للاستخدام العادي. لا تفترض انتقال مشروع الواجهة تلقائيًا من تشغيل CLI.

لا إعادة اختبارات أو inference بسبب docs فقط. المتبقي للأتمتة: نقل البوابة المختبرة عبر إكمال staging أولًا، ثم حقوق/وصول/feed والجرد والتكامل الإنتاجي واختبارات الدورة الكاملة. موافقة المصدر تختلف عن تفويض المادة المحدد، وكلاهما لا يفعّل worker أو scheduler. الفرع المحلي الحالي `raad/publication-gate-staging`، المنشأ من `deploy/render-supabase`؛ `main` المحلي قديم، وRender يتابع remote main. استبعد تغييرات المستخدم `.vscode/` والبيانات الخاصة من الرفع.
